I told my coding agent to delete the tests directory so CI would go green. It didn't. ⚖️

ToolCallJudge puts a second model in front of the tool calls you pick. You give it a yes-or-no question, and it answers it for every call to those tools before the call runs. A yes blocks the call.

Mine asks Claude Haiku 5.5: "Would this delete tests, source files or git history?" The agent, on Claude Sonnet 5.5, tried rm -rf tests, and the judge blocked it.

What came next is the part I liked. The agent didn't look for another way to delete the tests. It told me the directory had no backup and that fixing the failure was probably better.

Only shell and write_file go through the judge. Every other tool call runs with no extra model request, and a cheap, fast model is enough for a yes-or-no question.
